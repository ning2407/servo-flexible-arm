## 0. V20260921 版本变更（相对 V20260204）

1. **新增 §3.8 设置控制器编号**：全局广播 ID `0x4FE`，8 字节 `[N, 0x20, 0x26, 0x05, 0x20, 0x10, 0x58, 0x00]`（N=1..64，手册内部与 §3.1 的 1..60 冲突，组网按 1..60 使用）。⚠ 必须单台电机在线时写入，否则总线上所有电机被统一改号；写入后断电重启生效，全部 CAN ID 随新 N 变化。**旧版"无法改号"的结论作废**。
2. **新增 §3.7.1 校准指令帧格式**：`0x503+4N`，8 字节固定密钥 `55 AA CC 33 77 11 FF 00`，发送后自校准约 10 秒，期间禁止断电。旧版未公开负载，现已明确。
3. **新增 §3.7.2 校准结果帧格式**：`0x703+4N`，8 字节，data0 = 0x02 完成 / 0x03 错误，其余 0。
4. **回复/状态帧 data0~1 语义明确**：`data0 = 0x01 + 4N`，`data1 = 0x05`（N=1 时为 `05 05`），用于报文身份校验。
5. **FAQ 新增要点**：编码器为 21 位**单圈绝对值**（电机端、非输出端），多圈位置软件维护、**断电丢失**，上电建议以机械限位为多圈零点；位置码值是减速器前角度，输出端需除以减速比（例：65537≈11.25°，50:1 减速后输出仅 0.225°）；位置码值有效范围 ±2097151999（±0x7CFFFFFF，≈±1000 圈）。
6. §4 指令示意补充标准操作序列：MIT 定位 = `0005→0003→0001`；MIT 力控 = `0005→0003→0002`；速度模式 = `0007→0003→0009`；位置模式 = `0008→0003→0009`；校准 = `0005→0006`。
7. 厂商信息：指尖智擎；电机当前固定 4 Mbps 数据波特率，其他需求需联系厂家。
8. 实测补充（2026-10-08，HCANFD Pro-II 分析仪）：状态帧确实 20ms 周期广播（实测 ~51 帧/s）；MIT 回复一问一答；控制帧按 FD+BRS 发送可行。

## 3. CAN-FD 总线配置

| 参数 | 值 |
|---|---|
| 帧格式 | ISO CAN FD，11 位标准数据帧 |
| 仲裁段波特率 | 1 Mbps，采样点 80% |
| 数据段波特率 | 4 Mbps，采样点 80% |
| 终端电阻 | 总线两端各接 1 个 120 Ω |

**要点**

- 协议帧数据长度为 12 字节和 20 字节，这是 CAN FD 特有的 DLC，上位机必须使用支持 ISO CAN FD 的适配器；仅支持经典 CAN（≤8 字节）的设备无法通信。
- 120 Ω 终端电阻接在总线**两端**（首末节点），中间节点不接。

## 4. 节点编址与 ID 分配

N = 控制器编号（1..60）。每个节点占用 3 个发送 ID + 3 个接收 ID：

| 功能 | 方向 | CAN ID | DLC | 周期 / 触发 |
|---|---|---|---|---|
| MIT 模式发送 | 上位机 → 电机 | `0x501 + 4N` | 12 | 上位机周期发送 |
| 电机控制 | 上位机 → 电机 | `0x502 + 4N` | 8 | 事件发送（运行/停止/置零/切模式） |
| 编码器零点校准 | 上位机 → 电机 | `0x503 + 4N` | 未给出 | 仅校准时使用，平时避开 |
| MIT 模式回复 | 电机 → 上位机 | `0x701 + 4N` | 12 | 每收到一帧 MIT 发送帧回一帧 |
| 电机状态 | 电机 → 上位机 | `0x702 + 4N` | 20 | 20 ms 周期广播（50 Hz） |
| 校准结果返回 | 电机 → 上位机 | `0x703 + 4N` | 未给出 | 仅校准时使用，平时避开 |

N = 1（出厂默认）时的实际 ID：

| 功能 | ID |
|---|---|
| MIT 发送 | 0x505 |
| 电机控制 | 0x506 |
| 校准指令 | 0x507 |
| MIT 回复 | 0x705 |
| 电机状态 | 0x706 |
| 校准结果 | 0x707 |

接收侧分类建议：`off = id - (0x701 + 4N)`，`off==0` 为 MIT 回复，`off==1` 为状态帧，`off==2` 为校准结果。

## 5. 控制模式

| 模式 | 编码 | 控制量来源 | 说明 |
|---|---|---|---|
| MIT 模式 | 0x00 | 位置 + 速度 + Kp + Kd + 前馈电流 | **上电默认**；使用前必须先发"运行"命令 |
| 速度模式 | 0x01 | MIT 发送帧中的"速度"字段 | Kp/Kd 由固件固定参数决定，帧内 Kp/Kd 无效 |
| 位置模式 | 0x02 | MIT 发送帧中的"位置"字段（速度字段推断为运动速度） | Kp/Kd 由固件固定参数决定，帧内 Kp/Kd 无效 |

**模式切换规则**

- 通过电机控制帧（`0x502+4N`）的 data2 切换模式；
- 切换时电机必须处于停止状态（data0 = 0x00），否则模式切换不生效；
- 手册示例中的切模式指令（0005/0007/0008）都是"停止并进入 xx 模式"的组合操作。

## 6. 帧格式详解

### 6.1 MIT 模式发送（`0x501 + 4N`，12 字节）

方向：上位机 → 电机。用于 MIT 模式的全量控制，或速度/位置模式下的目标值下发（同一帧格式复用）。

| 字节 | 字段 | 编码 | 换算 |
|---|---|---|---|
| data0..3 | 位置码值 | s32 偏移二进制，**小端** | `raw = (d3<<24)\|(d2<<16)\|(d1<<8)\|d0`；`code = raw − 0x80000000`；`角度[°] = code / 2097152 × 360` |
| data4..5 | 速度码值 | s16 偏移二进制，**小端** | `raw = (d5<<8)\|d4`；`code = raw − 0x8000`；`转速[rpm] = code / 10` |
| data6..7 | Kp（位置环比例） | u16 **小端**，无符号 | `Kp = 0.00001 × u` |
| data8..9 | Kd（速度环比例） | u16 **小端**，无符号 | `Kd = 0.01 × u` |
| data10..11 | 前馈电流码值 | s16 偏移二进制，**小端** | `raw = (d11<<8)\|d10`；`code = raw − 0x8000`；`电流[A] = code × 11 / 4096` |

**字段细节**

- **位置**：多圈位置。编码器 21 位，一圈 360° = 2097152（= 2^21）刻度；分辨率 ≈ 0.0001717°/LSB；码值范围 ±0x7CFFFFFF ≈ ±1000 圈（0x7CFFFFFF = 2097151999 刻度 = 999.9999995 圈）。
- **速度**：码值范围 ±30000，对应 ±3000 rpm，分辨率 0.1 rpm。
- **Kp**：范围 0 ~ 0.65535，步长 1e-5。**初始建议 0.008**，过大会震荡。物理模型换算（输入 rad，输出 A）：`协议Kp = kact × 0.001115`，即 `kp_code = round(kact × 111.5)`。
- **Kd**：范围 0 ~ 655.35，步长 0.01。**初始建议 1**，过大会震荡。物理模型换算（输入 rad/s，输出 A）：`协议Kd = kact × 85.636`，即 `kd_code = round(kact × 8563.6)`。
- **前馈电流**：比例 11/4096 A/LSB ≈ 2.69 mA/LSB；理论满量程 ±32767 码 ≈ ±88 A（实际受电机能力限制）。
- **注意**：Kp/Kd/前馈电流仅在 MIT 模式有效；速度/位置模式下这些字段被忽略，固件使用自己的固定参数。

### 6.2 MIT 模式回复（`0x701 + 4N`，12 字节）

方向：电机 → 上位机。**每收到一帧 MIT 发送帧，回一帧**，可用作命令级确认和同步反馈。

| 字节 | 字段 | 说明 |
|---|---|---|
| data0..1 | ID 回显 | `data0 = 0x01 + 4N`，`data1 = 0x05`（即 `0x501+4N` 的 16 位小端，N=1 时为 `05 05`） |
| data2..5 | 电机位置码值 | 编码同发送帧位置字段 |
| data6..7 | 速度码值 | 编码同发送帧速度字段 |
| data8..9 | 电流码值 | `电流[A] = code × 11/4096` |
| data10..11 | 固定 0x00 | |

### 6.3 电机状态（`0x702 + 4N`，20 字节，20 ms 周期）

方向：电机 → 上位机，控制器每 20 ms 发送一帧，无需请求。

| 字节 | 字段 | 说明 |
|---|---|---|
| data0..1 | ID 回显 | 同 6.2 |
| data2..5 | 电机位置码值 | 编码同发送帧位置字段 |
| data6..7 | 速度码值 | 编码同发送帧速度字段 |
| data8..9 | 电流码值 | `电流[A] = code × 11/4096` |
| data10..11 | 母线电压 | `电压[V] = ((d11<<8)\|d10 − 0x8000) / 10`（小端偏移二进制；手册公式中的 `data1` 疑为 `data10` 笔误） |
| data12..15 | 故障状态 Fault | u32 **小端**：`fault = (d15<<24)\|(d14<<16)\|(d13<<8)\|d12`，位定义见第 8 节 |
| data16 | 电机状态 | 枚举见第 8 节 |
| data17 | 编码器零点校准状态 | 枚举见第 8 节 |
| data18 | 电机当前模式 | 枚举见第 8 节 |
| data19 | 电机类型 | 枚举见第 8 节 |

### 6.4 电机控制（`0x502 + 4N`，8 字节）

方向：上位机 → 电机。

| 字节 | 值 | 说明 |
|---|---|---|
| data0 | 0x01 / 0x00 | 0x01 = 电机运行；0x00 = 电机停止。**MIT 模式控制前必须先发运行命令** |
| data1 | 0x01 / 其他 | 0x01 = 将当前电机位置设置为 0 点位置（作用于位置控制）；其他值无效果 |
| data2 | 0x00 / 0x01 / 0x02 | 设置电机模式：0x00 = MIT、0x01 = 速度、0x02 = 位置。**改变模式时必须先停止（data0=0x00）才生效** |
| data3..7 | 0x00 | 保留 |

### 6.5 编码器零点校准 ID（`0x503 + 4N` / `0x703 + 4N`）

- `0x503+4N`：编码器零点校准指令；`0x703+4N`：返回校准结果。
- 手册明确要求用户平时**避开**这两个 ID，防止误操作/冲突。
- **手册未给出校准指令的数据负载格式**，示例中的"0006 校准指令"也没有给出帧字节，使用前需向厂家确认（见第 11 节）。

## 7. 数值编码规则汇总

所有多字节字段均为**小端**（低字节在低 data 序号），有符号量采用**偏移二进制**：

| 物理量 | 字节 | 编码 | 换算公式 | 分辨率 | 范围 |
|---|---|---|---|---|---|
| 位置 | 4 | s32 偏移二进制 | `° = code / 2097152 × 360` | ≈0.0001717° | ±0x7CFFFFFF（≈±1000 圈） |
| 速度 | 2 | s16 偏移二进制 | `rpm = code / 10` | 0.1 rpm | ±3000 rpm |
| 前馈/反馈电流 | 2 | s16 偏移二进制 | `A = code × 11/4096` | ≈2.69 mA | 理论 ±88 A |
| 母线电压 | 2 | s16 偏移二进制 | `V = code / 10` | 0.1 V | — |
| Kp | 2 | u16 原码 | `Kp = u × 1e-5` | 1e-5 | 0 ~ 0.65535 |
| Kd | 2 | u16 原码 | `Kd = u × 0.01` | 0.01 | 0 ~ 655.35 |
| 故障字 | 4 | u32 原码 | 位域 | — | 32 位 |

**编码步骤**（以 16 位有符号为例）：

```text
raw = (code + 0x8000) & 0xFFFF     # 编码：有符号 → 偏移二进制
d_lo = raw & 0xFF                   # 低字节放低序号 data
d_hi = (raw >> 8) & 0xFF
code = raw - 0x8000                 # 解码：偏移二进制 → 有符号
```

## 9. 典型操作时序（来自手册第 4 节）

手册示例编号 0001..0009 为指令示意，不是 CAN ID：

| 编号 | 指令 | 内容 |
|---|---|---|
| 0001 | 设置 MIT 模式下的位置 | 25/30mm 建议 Kp=0.008、Kd=1；示例帧 `010000900080200364000080` |
| 0002 | 设置 MIT 模式下的电流 | 示例帧 `010001800080000000006480`（前馈电流码值 100） |
| 0003 | 电机运行指令 | 控制帧 data0=0x01 |
| 0004 | 当前位置置 0 点 | 电机停止，并进入 MIT 模式 |
| 0005 | 停止并进入 MIT 模式 | 控制帧 data0=0x00, data2=0x00 |
| 0006 | 校准指令 | 发往 `0x503+4N`，负载 `55 AA CC 33 77 11 FF 00`（§3.7.1） |
| 0007 | 停止并进入速度模式 | 控制帧 data0=0x00, data2=0x01 |
| 0008 | 停止并进入位置模式 | 控制帧 data0=0x00, data2=0x02 |
| 0009 | 位置/速度模式下设置目标 | 示例：速度 2000 rpm，位置 0x20000001 |

### 操作流程

1. **MIT 位置控制**：发 0005（停止→MIT）→ 0003（运行）→ 持续发送 0001 位置帧
2. **MIT 电流控制**：发 0005 → 0003 → 持续发送 0002 电流帧
3. **速度模式**：发 0007（停止→速度模式）→ 0003（运行）→ 发送 0009（帧内速度字段=目标转速），示例电机以 2000 rpm 运行
4. **位置模式**：发 0008（停止→位置模式）→ 0003（运行）→ 发送 0009（帧内位置字段=目标位置），示例电机运行到 0x20000001
5. **编码器零点校准**：发 0005 → 0006，然后等待约 10 s，通过状态帧 data17 判断结果（2=完成，3=错误）

## 11. 已知歧义与待确认问题（向厂家核实清单）

| # | 问题 | 现状与建议 |
|---|---|---|
| 1 | 字节序 | 手册公式按"data3 是最高字节"组装（即小端），全部示例帧与此吻合，**可确认小端**。实现时切勿按大端组包 |
| 2 | 状态帧电压公式笔误 | 手册写 `((u16)data11<<8)\|((u16)data1)`，按上下文应为 `data10`，本知识库按 data10 修正 |
| 3 | 校准指令负载 | `0x503+4N` 的数据格式手册未给出，示例 0006 也无帧内容。校准会旋转电机，使用前必须向厂家确认流程 |
| 4 | ~~节点号修改~~ | ✅ **已解决**（V20260921 §3.8：`0x4FE` 广播 `[N,20,26,05,20,10,58,00]`，单台在线写入+断电重启生效） |
| 5 | ~~位置模式下速度字段语义~~ | ✅ **已实测（2026-10-08）**：该固件位置模式**忽略** MIT 帧中的速度字段（不同速度设定运动时间不变）。控速请用 MIT 模式流式下发梯形轨迹（p_des 连续 + v_des=导数），GUI 已内置 |

## 12. 上位机实现检查清单

- [ ] CAN-FD 适配器：ISO CAN FD，仲裁 1 Mbps / 数据 4 Mbps，采样点 80%
- [ ] 总线两端 120 Ω 终端电阻，示波器/分析仪确认信号质量
- [ ] 供电 12 V 标称（10–18 V），电源电流能力按电机功率留余量
- [ ] 接收过滤器：`0x701+4N`（命令回执）、`0x702+4N`（状态）；校准时再加 `0x703+4N`
- [ ] 上电后等待状态帧（20 ms 内应有），确认 data16 电机状态、data18 模式（默认 MIT）、data19 电机类型
- [ ] MIT 控制前先发运行命令（0x502+4N, data0=0x01）
- [ ] 切模式前先发停止（data0=0x00），再改 data2
- [ ] 周期监控故障字（data12..15）与母线电压（data10..11）
- [ ] 多节点（最多 60 台）时评估总线负载：仅状态帧就是 60×50 Hz = 3000 帧/s，20 字节 FD 帧估算约占总线三成以上；高频 MIT 控制需按节点数规划发送频率

### 14.1 Windows / Linux API 差异（transport 层已屏蔽）

| 差异点 | Windows | Linux |
|---|---|---|
| 初始化 | 无 | 必须 `LibCANbus_Init()`，退出 `LibCANbus_Exit()` |
| 函数参数 | `f(devNum)`，devNum 即通道号 | `f(devNum, chNum)`；双通道=设备0+通道0/1 |
| 设备类型函数 | `CAN_GetDevType(dev)` | `CAN_GetCHType(dev, ch)` |
| 调用约定 | WinDLL(stdcall) | CDLL(cdecl) |
| 加载 | HCanbus.dll | 先全局加载 libusb-1.0，再 libcanbus.so |
| 采样点回填 | 数据段 80%（与请求一致） | 数据段 75%（实测通信正常，见 14.2） |
| 权限 | WinUSB 免驱 | udev 规则：`ATTRS{idVendor}=="a8fa", ATTRS{idProduct}=="8598", GROUP="plugdev", MODE="0666"` |

### 14.2 Linux 部署要点（Ubuntu 20.04 实测）

```bash
sudo tar -xf libcanbus(ubuntu20).tar -C /usr/local/lib/ && sudo ldconfig
sudo cp hcanbus.rules /etc/udev/rules.d/99-hcanbus.rules
sudo udevadm control --reload-rules && sudo udevadm trigger
```

### 14.3 SDK 编程要点（踩坑记录）

1. **Receive 语义**：`CANFD_Receive` 收到任意一帧立即返回（非攒满/等满超时）——必须循环收。
2. **返回值**：Open/Init/Close=0成功；Transmit/Receive=实际帧数；Scan=设备数。
3. **DLC≠长度**：DLC 9..15 → 12..64 字节（CAN FD 规范映射）。
4. **线程安全未声明**：收/发/关闭并发可死锁（实测）——所有 DLL 调用必须串行化
   （transport 层已用 RLock 保护全部入口）。
5. ctypes 细节：结构体数组字段用 `c_ubyte` 而非 `c_char`（后者遇 0x00 截断，曾致收帧数据残缺）。
6. GUI 关闭路径：不要在 UI 线程 join+关设备（曾死锁）；进程退出让 OS 回收句柄。
7. **Linux 必须先 `CAN_ScanDevice()` 再 `CAN_OpenDevice()`**：USB 重枚举后设备号会变
   （Bus003 Dev004→005），不先 Scan 则 Open 报"通道不存在/被占用"（实测踩坑；厂商
   示例同为先 Scan 后 Open）。transport.open() 已内置。
8. **Linux `LibCANbus_Init/Exit` 必须严格配对且全进程一次**：多实例需引用计数（首个
   open 时 Init、最后一个 close 时 Exit）。曾用 atexit+新建 CDLL 调 Exit，触发 libusb
   `pthread_mutex_destroy` 断言崩溃（双重清理）；已改为模块级计数管理。

## 16. 软件架构（2026-10-09 重构定稿）

```
motorapi/                  ← 交付同事的 Python 控制库（零第三方依赖，Win/Linux）
├── transport.py           适配器驱动：跨平台加载、80%采样点时序计算、收发锁
├── codec.py               协议编解码（本知识库全部帧型 + 自检）
└── motor.py               MotorApi 高层接口（唯一对外入口）
tools/motor_gui.py         上位机 = 纯 MotorApi 调用（无业务逻辑）
examples/api_examples.py   API 示例 ×5
docs/api.md                API 详细文档（交付版）
```

关键设计：
- **速比计算全部在 API**（send_mit/run_*/trajectory/状态解码/限幅），GUI 零换算逻辑；
- 回调（status/frame/reply/tx/calibration）在工作线程触发，GUI 用队列转发；
- MIT 连续发送支持运行中实时改参（`set_streaming_params`，自定义轨迹外环）；
- 轨迹线程 100Hz 梯形规划（短行程自动三角化），abort 立即停机。
